# ナイトレイン地図表示ツール

## 概要

ゲームの攻略拠点の地図を表示する

## 用語

| 用語   | 意味                                                             |
| ------ | ---------------------------------------------------------------- |
| 拠点   | ゲーム内の攻略拠点。例: 大教会 (great-church)                    |
| タイプ | 同じ拠点に存在する地図のバリエーション。タイプA / タイプB と呼ぶ |
| 階層   | 1つのタイプが持つフロア。例: 2F / 1F / B1                        |

構造は「拠点 → タイプ → 階層 → 画像」の3段になる。
地上マップ・地下マップといった区分は存在しない。B1 は単に地下1階を表す階層である。

## URL

`/nightreign/maps` に一覧ページを作成、maps以下に個別の拠点の地図を置く。
例えば `great-church` の地図ならば `/nightreign/maps/great-church` となる。

1つの拠点に属する地図はすべて1ページに載せる。タイプごとに個別のURLは作らない。
選択中の階層はURLに反映しない（ページ内の一時状態として持つ）。

| URL                        | 内容                                 |
| -------------------------- | ------------------------------------ |
| `/nightreign/maps/`        | 拠点一覧。既存ページと同じカード形式 |
| `/nightreign/maps/[slug]/` | 拠点ページ。`getStaticPaths` で生成  |

ツールの呼び名は「拠点地図」とし、一覧ページの h1・パンくず・title/OGP・`/nightreign/` のカードすべてで使う。
`/nightreign/` の links に「拠点地図」のカードを追加して導線を張る。

## UI

細かいデザインは異なるが、 `.claude/specs/map_layout_sample.png` を用意した。左に階層を選択するUIがあり、中央に地図画像を表示する。
選択された階層の地図画像のみ表示する。

### レイアウト

拠点ページはタイプごとのセクションを縦に並べ、各セクションが自分の階層セレクタと地図を持つ。
タイプが1つしかない拠点では「タイプA」の見出しを省略する。

```
[タイプAの見出し(タイプが2つ以上のときのみ)]
  [2F]      ┌──────────────┐
  [1F]◀     │   地図画像    │
  [B1]      └──────────────┘

[タイプBの見出し]
  [1F]      ┌──────────────┐
  [B1]◀     │   地図画像    │
            └──────────────┘
```

- 階層セレクタは daisyUI の `btn` を縦に並べる。選択中は `btn-primary`、未選択は `btn-outline`。
- スマホ（`< sm`）では階層セレクタを地図の上に横並びで置き、`sm` 以上で左に縦並びにする。
- `Layout` に幅を渡す prop を追加し `Header` へ伝播させる。地図ページのみ幅を広げる（既存2ページはデフォルト値の `max-w-2xl` のまま）。
- 拠点ページの末尾に既存 quiz ページと同じ免責フッターを置く。一覧ページには置かない。
- 一覧ページのカードは拠点名のみ。説明文・サムネイルは出さない。

### 階層の切り替え

`radio` + CSS のみで実装し、JavaScript は使わない。

- 階層ごとに `<input type="radio">` を置き、`:checked` と兄弟セレクタで対応する画像を表示する。
- 複数タイプのセクションが同居するため、`radio` の `name` はタイプごとに分ける。
- 全階層の画像を DOM に置き、すべて通常読み込みする（`lazy` にしない）。1URLあたり最大6枚程度を想定しており、切り替え時のちらつきを避けることを優先する。

### 表示順と初期表示

- 階層は定義ファイルの配列順に表示する。上層から下層の順で並べる（画面上の位置と階層の上下を一致させる）。
- 初期選択はタイプごとに `defaultFloor` で明示する。大教会タイプAは `1f`。
- `defaultFloor` が `floors` の id と一致することは型で強制する。実行時のフォールバックは行わない。

### テーマ

地図画像は黒背景・白線のため、ライトテーマでは白地に黒い矩形が浮く。
**暫定対応として**、地図画像を包むコンテナに常時暗い背景を敷く。ライトテーマ用画像が揃った時点でこの背景は撤去する。

## データ

### 定義ファイル

拠点の定義は `src/data/` に TypeScript で持つ。拠点の追加が1ファイルの編集で済む形にする。

```ts
defineMap({
  slug: "great-church",
  englishName: "Great Church", // translations.yaml のキー
  types: [
    {
      id: "a",
      defaultFloor: "1f",
      floors: [
        { id: "2f", label: "2F", images: { dark: img2f } },
        { id: "1f", label: "1F", images: { dark: img1f } },
        { id: "b1", label: "B1", images: { dark: imgB1 } },
      ],
    },
  ],
});
```

- `floors` はタイプごとに独立して持つ。タイプによって階層構成が異なる場合があるため。
- `defineMap` は `floors` の id から union を導き、`defaultFloor` をその union に限定するヘルパーとする。
- `images` は将来のテーマ別画像を見越して `{ dark, light? }` の形で持つ。現在は `dark` のみ。

### 拠点名の対応表

英名→日本語名は `data/nightreign_translations.yaml` に `# --- Location ---` セクションを追加して持つ。

```yaml
# --- Location ---
Great Church: "大教会"
```

拠点定義の `englishName` が yaml のキーに対応する。slug からの自動変換は行わない。

yaml のパーサは現在 `quiz.astro` に直書きされているため、地図ページでの利用に先立って `src/` へ切り出して共通化する。

### 画像ファイル

地図の画像は `src/assets/maps/<slug>/` に置き、`astro:assets` の `<Image>` で扱う。

```
src/assets/maps/great-church/
  great_church_1f_type_a.webp
  great_church_2f_type_a.webp
  great_church_b1_type_a.webp
```

- ディレクトリ名は slug と同じケバブケース、ファイル名はスネークケース。
- ファイル名には拠点名・階層・タイプを含める。`underground` は地上/地下の区分を意味しないため付けない。
- 元の `data/great_church_underground_*.webp` は移動に伴い削除する。

## 将来の拡張

### ピン

地図上に宝箱・ボス位置などのピンを載せる予定がある。今回は受け皿だけ用意する。

- 地図画像を `relative` なコンテナに包み、後からピンを重ねられるマークアップにしておく。
- 座標は画像に対するパーセントで持つ（表示サイズに依存せず、画像を差し替えても崩れないため）。
- 1つのピンは「種別 + ラベル + 座標」を持つ。種別でアイコンと色を切り替える想定。
- 座標データが存在しないため、ピンの型定義と描画は今回は実装しない。

### テーマ別画像

ライトテーマ用の地図画像を後日用意し、`images` の `light` / `dark` を `prefers-color-scheme` で切り替える。
ライト用とダーク用は色違いの同一構図で作る。そのためピン座標は階層につき1組だけ持てばよい。

## 実装の進め方

機能追加とリファクタリングでコミットを分ける。リファクタリングを先に行う。

1. リファクタリング: yaml パーサを `quiz.astro` から `src/` へ切り出す
2. 機能追加: 画像の移動、translations への拠点追加、一覧ページと拠点ページの作成、`/nightreign/` への導線追加
