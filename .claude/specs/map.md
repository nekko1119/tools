# ナイトレイン地図表示ツール

## 概要

ゲームの攻略拠点の地図を表示する

## 用語

| 用語   | 意味                                                             |
| ------ | ---------------------------------------------------------------- |
| 拠点   | ゲーム内の攻略拠点。例: 大教会 (great-church)                    |
| タイプ | 同じ拠点に存在する地図のバリエーション。タイプA / タイプB と呼ぶ |
| 階層   | 1つのタイプが持つフロア。例: 2F / 1F / B1                        |

構造は「拠点 → タイプ → 階層 → 画像」の3段になる。
地上マップ・地下マップといった区分は存在しない。B1 は単に地下1階を表す階層である。

## URL

`/nightreign/maps` に一覧ページを作成、maps以下に個別の拠点の地図を置く。
例えば `great-church` の地図ならば `/nightreign/maps/great-church` となる。

1つの拠点に属する地図はすべて1ページに載せる。タイプごとに個別のURLは作らない。
選択中の階層はURLに反映しない（ページ内の一時状態として持つ）。

| URL                        | 内容                                 |
| -------------------------- | ------------------------------------ |
| `/nightreign/maps/`        | 拠点一覧。既存ページと同じカード形式 |
| `/nightreign/maps/[slug]/` | 拠点ページ。`getStaticPaths` で生成  |

ツールの呼び名は「拠点地図」とし、一覧ページの h1・パンくず・title/OGP・`/nightreign/` のカードすべてで使う。
`/nightreign/` の links に「拠点地図」のカードを追加して導線を張る。

## UI

細かいデザインは異なるが、 `.claude/specs/map_layout_sample.png` を用意した。左に階層を選択するUIがあり、中央に地図画像を表示する。
選択された階層の地図画像のみ表示する。

### レイアウト

拠点ページには地図を1枚だけ置き、セレクタは「パターン」と「階層」の2つとする。
地図はヘッダーと免責フッターを除いた領域を上下左右いっぱいに使い、
セレクタと凡例はその上に重ねる。地図が使える面積を最大にするため。

```
┌──────────────────────────────┐
│ ヘッダー(パンくず)             │
├──────────────────────────────┤
│ 大教会 [無(霊廟騎士)][炎(火の僧兵)] │
│ [2F]                         │
│ [1F]◀        地図画像         │
│ [B1]                         │
│ □宝箱 ○遺体         [+][−][⟲] │
├──────────────────────────────┤
│ フッター(免責)                 │
└──────────────────────────────┘
```

タイプ専用のセレクタは設けない。アイテムの配置はタイプをまたいで重複しないため、
パターンを選べば地図のタイプも一意に決まる。セレクタには全タイプのパターンをまとめて並べる。
ボタンにはパターン名だけを出す。名前がユニークなので、タイプ名がなくても選び分けられる。

- ページの高さは `100dvh` に固定し、ページ自体はスクロールさせない。地図の領域はヘッダーとフッターの残り全部とする。
- 地図の領域だけ `max-w-7xl` の外に出して画面の端まで使う。ヘッダーとフッターの中身は `max-w-7xl` の中央寄せのまま揃える。
- 重ねるものは4つ。拠点名とパターンを上端に、階層を左端に、凡例を下端の左に、拡大操作を下端の右に置く。
- 地図は重ねたUIの下に潜らせ、領域の全幅を使う。UIの分だけ地図を縮めない。
- 階層セレクタは daisyUI の `btn` を縦に並べる。選択中は `btn-primary`、未選択は `btn-outline`。
  画面幅で並べ方を変えず、スマホでも左端に縦並びにする。
- 重ねるUIは地図の線に紛れないよう、背後を地の色の半透明とぼかしで落とす。拠点名も同じ扱いにする。
- 拠点名は `h1` として地図の上に重ねる。パンくずの末尾と同じ名前になるが、見出しの構造のために置く。
- 凡例はドラッグの邪魔をしないよう、ポインタのイベントを受け取らない。
- `Layout` に幅を渡す prop を追加し `Header` へ伝播させる。地図ページのみ `max-w-7xl` まで広げる（既存2ページはデフォルト値の `max-w-2xl` のまま）。
- 地図ページは専用の `MapLayout` を使う。`Layout` との違いは body の組み方だけなので、`head` の中身は `BaseHead` に切り出して共通化する。
- 拠点ページの末尾に既存 quiz ページと同じ免責フッターを置く。一覧ページには置かない。
- 一覧ページのカードは拠点名のみ。説明文・サムネイルは出さない。

### 階層の切り替え

`radio` + CSS のみで実装し、階層の切り替えに JavaScript は使わない。

- 階層ごとに `<input type="radio">` を置き、`:checked` と兄弟セレクタで対応する画像を表示する。
- 全タイプの階層セレクタが同居するため、`radio` の `name` はタイプごとに分ける。
- 全階層の画像を DOM に置き、すべて通常読み込みする（`lazy` にしない）。1URLあたり最大6枚程度を想定しており、切り替え時のちらつきを避けることを優先する。

パターンを切り替えてタイプが変わるときは、選んでいた階層をできるだけ引き継ぐ。

- 切り替え先のタイプに同じ階層 id があればそれを選ぶ。
- 無ければ切り替え先の `defaultFloor` を選ぶ。

### 地図の拡大縮小

表示領域の大きさは変えずに、中の地図だけを拡大縮小して見られるようにする。ここだけは JavaScript を使う。

- 表示領域はヘッダーとフッターを除いた領域そのものとする。地図はこの中を動き、はみ出した分は隠す。
- 等倍の地図は、表示領域に収まる最大の大きさ（画像のアスペクト比 2338:1654 のまま）にして中央に置く。
  画面と地図で縦横比が違うため上下または左右に余りが出る。
  大きさは領域を基準にしたコンテナクエリの単位で決め、`min()` で幅と高さのどちらで頭打ちになっても比率を保つ。
- 余りも表示領域の一部なので、その上でもドラッグやピンチを受け付ける。
- 倍率は 1倍〜3倍の連続値。1倍で全体が枠に収まり、3倍（約2400px）が原寸とほぼ一致するため画質が破綻しない。
- 初期表示は、地図が表示領域を埋める倍率にする（上限は3倍）。
  地図と画面で縦横比が違うため縦か横は画面の外に出るが、全体が収まる倍率では
  縦長の画面で地図が小さくなりすぎるため、余白を残さないことを優先する。
  全体を見たいときは縮小する。表示領域と地図の縦横比が近ければ、この倍率は1倍に近づく。
- 拡大しても粗くならないよう、画像の `sizes` は最大倍率ぶんの表示幅を見込んで指定する。
- 操作方法は以下の4つ。
  - ピンチ: 2本指の間隔で拡大縮小する。指の中点を基準にする。トラックパッドのピンチは ctrl 付きのホイールとして届くため、これも同じ操作として扱う。
  - ドラッグ / 1本指スワイプ: 拡大中の表示位置を動かす。
  - ダブルクリック / ダブルタップ: その位置を中心に拡大する。上限に達している場合は1倍に戻す。
  - `+` / `-` / リセットのボタン。リセットは初期表示に戻す。
- 素のホイールは拡大縮小に使わない。ページがスクロールしない作りでは何も起きない操作になるが、
  意図せず倍率が変わる事故を避けることを優先する。拡大はピンチ・ダブルクリック・ボタンで行う。
- ボタンは領域の右下に1組だけ重ねる。ピンチが使えない環境と、キーボードだけの操作を成り立たせるため。
  倍率は拠点単位で1つなので、階層ごとにボタンを持つ必要はない。
- 表示位置は、地図のどの端も表示領域の中央まで寄せられる範囲に収める。
  端にあるものを画面の中央へ持ってこられるようにするため、等倍の地図の半分を余分な可動域として足す。
  地図は表示領域の中央に置かれるため、半分ぶん動かせれば端がちょうど中央に届く。
- 等倍でも地図を動かせる。重ねたUIに隠れた端を見られるようにするため。中央には「リセット」で戻す。
- 倍率と表示位置は拠点単位で持ち、階層を切り替えてもパターンを切り替えても維持する。
  同じ場所の上下の階や、同じ場所の別パターンを見比べられるようにするため。

実装は、全階層の画像を包む変形レイヤーに `transform: translate() scale()` をかけ、その値を CSS カスタムプロパティで渡す。
値は拠点ページ全体を包む要素に持たせ、どのタイプの地図にも同じ変形がかかるようにする。
階層ごとの画像は個別に変形せず共通のレイヤーに乗るため、切り替えても倍率と位置がそのまま保たれる。

ページがスクロールしないため、タッチは倍率によらず常に地図の操作に使う（`touch-action: none`）。

枠の大きさが変わると移動できる範囲も変わるため、`ResizeObserver` で枠を監視して表示位置を補正する。
スマホでアドレスバーが伸び縮みしたときに `resize` が発火しないことがあり、`window` の `resize` では取りこぼすため。

### 表示順と初期表示

- 階層は定義ファイルの配列順に表示する。上層から下層の順で並べる（画面上の位置と階層の上下を一致させる）。
- 初期選択はタイプごとに `defaultFloor` で明示する。大教会タイプAは `1f`。
- `defaultFloor` が `floors` の id と一致することは型で強制する。実行時のフォールバックは行わない。

### テーマ

地図画像はテーマごとに用意する。ダーク用は黒背景・白線、ライト用は白背景・黒線で、構図は同じにする。

- `prefers-color-scheme` で切り替える。`<picture>` の `<source media>` に任せ、JavaScript は使わない。
- 表示領域の下地はテーマの色に追従させる。画像が読み込まれるまでの間だけ見える。

## データ

### 定義ファイル

拠点の定義は `src/data/` に TypeScript で持つ。拠点の追加が1ファイルの編集で済む形にする。

```ts
defineMap({
  slug: "great-church",
  englishName: "Great Church", // translations.yaml のキー
  types: [
    {
      id: "a",
      defaultFloor: "1f",
      floors: [
        { id: "2f", label: "2F", images: { dark: img2f } },
        { id: "1f", label: "1F", images: { dark: img1f } },
        { id: "b1", label: "B1", images: { dark: imgB1 } },
      ],
    },
  ],
});
```

- `floors` はタイプごとに独立して持つ。タイプによって階層構成が異なる場合があるため。
- `defineMap` は `floors` の id から union を導き、`defaultFloor` をその union に限定するヘルパーとする。
- `images` はテーマごとに `{ dark, light? }` の形で持つ。`light` が無い階層はダーク用の画像だけを使う。

### 拠点名の対応表

英名→日本語名は `data/nightreign_translations.yaml` に `# --- Location ---` セクションを追加して持つ。

```yaml
# --- Location ---
Great Church: "大教会"
```

拠点定義の `englishName` が yaml のキーに対応する。slug からの自動変換は行わない。

yaml のパーサは現在 `quiz.astro` に直書きされているため、地図ページでの利用に先立って `src/` へ切り出して共通化する。

### 画像ファイル

地図の画像は `src/assets/maps/<slug>/` に置き、`astro:assets` の `<Image>` で扱う。

```
src/assets/maps/great-church/
  great_church_type_a_dark_2f.webp
  great_church_type_a_dark_1f.webp
  great_church_type_a_dark_b1.webp
  great_church_type_a_light_2f.webp
  great_church_type_a_light_1f.webp
  great_church_type_a_light_b1.webp
```

- ディレクトリ名は slug と同じケバブケース、ファイル名はスネークケース。
- ファイル名は `拠点_タイプ_テーマ_階層` の順とする。`underground` は地上/地下の区分を意味しないため付けない。
- ダークテーマ用の画像にも `dark` を付け、ライトテーマ用と同じ並びに揃える。
- 元の `data/great_church_underground_*.webp` は移動に伴い削除する。

## アイテムの配置

地図の上に宝箱や遺体のアイコンを重ねて、何がどこにあるかを示す。

### 配置パターン

アイテムの配置は複数ありうる。パターンはタイプをまたいで重複せず、必ずどれか1つのタイプに属する。
そのため構造は「拠点 → パターン → 階層 → アイテム」の3段とし、パターンがどのタイプの地図を使うかを持つ。

パターンは階層セレクタとは別軸のセレクタで切り替える。
パターンを選ぶと、それが指すタイプの地図に切り替わり、そのパターンのアイコンだけが重なる。
パターンの名前は配置ファイルで自由に付ける。画面上は「パターン」と呼ぶ。

### 配置ファイル

拠点ごとに `data/map-items/<slug>.yaml` を置く。手で編集するファイルなので、コメントを書ける yaml とする。

```yaml
# 座標は地図画像の原寸(2338x1654)を基準としたピクセル値
patterns:
  - name: パターン1
    type: a
    floors:
      1f:
        - { item: common_chest, x: 994, y: 513 }
        - { item: corpse, x: 1200, y: 800 } # 祭壇の裏
      2f:
        - { item: rare_chest, x: 500, y: 400 }
```

- `type` は地図定義の `types[].id` に対応する。このパターンでどの地図を表示するかを決める。
- `floors` のキーは、そのタイプの `floors[].id` に対応する。アイテムが無い階層は省略できる。
- 座標は画像の原寸ピクセル値で書く。画像を開いて読んだ値をそのまま書けるようにするため。描画時に割合へ換算する。
- `item` はアイテム種別の識別子。定義されていない値を書いた場合はビルドを失敗させる。

手編集で生じた誤りに気づけるよう、ビルド時に以下を検証してエラーにする。

- 存在しないタイプ・階層・アイテム種別を指していないか
- 座標が画像の範囲内に収まっているか
- パターンの名前が重複していないか（セレクタで区別できなくなるため）

### アイテム種別

種別ごとの見た目と表示名は `src/data/` に TypeScript で定義する。画像の import が必要なため。

アイコンはすべて線画の SVG とする。

| 識別子         | 見た目                             |
| -------------- | ---------------------------------- |
| `common_chest` | `chest.svg` を黄みのオレンジで塗る |
| `rare_chest`   | `chest.svg` を灰色で塗る           |
| `corpse`       | `corpse.svg`                       |
| `sacred_seal`  | `sacred_seal.svg` を灰色で塗る     |

宝箱は2種とも同じ `src/assets/map-items/chest.svg` を使い、内側の塗り色だけで区別する。
形が揃っていれば地図上で宝箱だと分かり、色でレア度を表せるため。
通常の宝箱は実際には茶色だが、暗い地図の上で沈むため視認性を優先して黄みのオレンジにする。

`chest.svg` は塗り分けのため内側の色だけを `--chest-fill` で受け取る。
CSS 変数を効かせるため、`img` 要素ではなくインラインで埋め込む。

### アイコンの表示

- 短辺が 32px になるよう、元画像の比率を保ったまま縮小する。
  大きさは種別ごとに変えられるようにする。遺体は円だけの単純な形なので 16px とする。
  地図が画面いっぱいに広がるため、地図に対して小さくなりすぎない大きさにする。
- 狭い画面（`40rem` 未満）では半分の大きさにする。
  画面が狭いほど地図に対してアイコンが大きく見えるため、画面幅で出し分ける。
- 座標がアイコンの中心になるよう配置する。
- 地図を拡大してもアイコンの大きさは変えず、位置だけ追従させる。拡大率に関わらず見分けられるようにするため。
  そのためアイコンは地図画像の変形レイヤーの外に置き、座標にだけ拡大率と表示位置を反映する。
- 見やすくするための装飾は CSS で足さず、アイコンの SVG 自身に持たせる。
- 塗りを持たない線だけのアイコンは、縮小すると線が細くなって消える。
  `vector-effect="non-scaling-stroke"` を指定し、表示の大きさに関わらず線の太さを保つ。
- 線が離れていて閉じていないアイコンは、輪郭を1本の閉じたパスにまとめてから塗る。
  小さく表示しても形が塊として見えるようにするため。抜きたい部分は `fill-rule="evenodd"` で穴にする。
- どのアイコンが何を指すかを示す凡例を、地図の上に重ねて下端の左に置く。
  凡例には定義されている種別を常にすべて並べる。階層やパターンを切り替えても内容が変わらないようにするため。
- 色はテーマに追従させず SVG 内で固定する。地図はテーマごとに明暗が反転するため、
  どちらでも見えるよう「明るい塗り」と「暗い線」の組み合わせに揃える。
  塗りがテーマによらず一定なら、明るい地図でも暗い地図でもアイコンとして浮く。

## 実装の進め方

機能追加とリファクタリングでコミットを分ける。リファクタリングを先に行う。

1. リファクタリング: yaml パーサを `quiz.astro` から `src/` へ切り出す
2. 機能追加: 画像の移動、translations への拠点追加、一覧ページと拠点ページの作成、`/nightreign/` への導線追加
